# AGENTS.md: working on TanchTV

Notes for anyone continuing this project, human or AI agent (Claude Code, Codex, Antigravity,
Grok, ...). To **install** TanchTV for a user, follow [`AGENT_SETUP.md`](AGENT_SETUP.md) instead.

## What it is

A self-hosted web app that shows HDMI capture cards in the browser and remote-controls the TV box
behind each card. One card + one box = a **port**. Two containers (see `docker-compose.yml`):

- **`tanchtv-stream`**: stock go2rtc 1.9.15. Its config (`go2rtc/go2rtc.yaml`) is *generated by
  the app*; `go2rtc/capture.sh` is the per-port capture/encode pipeline it runs.
- **`tanchtv-app`**: everything else, in plain Python (aiohttp) and vanilla JS. No build step.

## Layout

```
app/
  server.py      aiohttp app: auth middleware, sign-in (password, passkeys, Google OAuth), admin APIs,
                 ports API + go2rtc config sync, video WebSocket proxy (/api/ws), VLC links (ffmpeg
                 remux to MPEG-TS with PCR), viewer sessions + idle reaper, no-signal detector.
  remotes.py     Remote drivers: BaseRemote (state machine, reconnect loop), AdbMixin,
                 AndroidTVRemote (androidtvremote2 + optional ADB), FireTVRemote (ADB),
                 AppleTVRemote (pyatv: AirPlay + Companion + MRP). KEYS / APPS tables. Remotes manager.
  ports.py       Capture-device discovery from sysfs (USB path, name, audio card), go2rtc YAML builder.
  db.py          SQLite schema + helpers: users, sessions, invites, passkeys, stream_links, ports, settings.
  cli.py         Admin CLI (built-in admin password/enable/disable, users, logout-all).
  static/        index.html (whole player + settings UI, one ES module), login.html, passkey.js,
                 app.css (shared tokens/buttons), logos/icons, slate-photo.jpg (no-signal card photo).
go2rtc/
  capture.sh             capture.sh <usb-path> <rtsp-output>: finds card + ALSA by USB path, ffmpeg encode.
  go2rtc.example.yaml    starting config (copied to go2rtc.yaml, which is git-ignored and app-managed).
docs/screenshots/        images used by the README.
```

Data (git-ignored, back it up): `data/tanchtv.db` (older installs: `tvremoter.db`, still used if
present) and `data/ports/<id>/` (pairing certificates, ADB keys).

## How the pieces talk

- Browser → app: cookie session (`tvr_session`, 30 days). `auth_mw` guards everything except
  `PUBLIC_PATHS`. Roles: `admin`, `viewer` (+ `can_control`). Decorators: `@admin_only`, `@control_only`.
- Video: the page's `TvPlayer` (subclass of go2rtc's `VideoRTC`, served from go2rtc at
  `/video-rtc.js`) opens `/api/ws?sid=&port=&q=sd`; the app proxies to go2rtc's WS for stream
  `p<id>` or `p<id>_sd`. WebRTC is negotiated over that WS and then flows directly from go2rtc
  (:8555) to the browser; if it can't connect, MSE data flows through the WS instead.
- Control channel: `/api/session?sid=` WebSocket; the page reports `{mode, visible, playing, path,
  quality, port}` every 5 s; the server can send `kill`. The reaper stops sessions paused or
  silent for `IDLE_KILL_SECONDS` (hidden-but-playing is fine; `mode: "remote"` pages are never
  idle-killed). Remote keys also travel on this socket (`{type: "key", seq, port, key, direction}`
  → `{type: "keyack", seq, ok, error?}`, run in order per page) instead of one HTTP POST each.
- Remote mode (`uiMode === 'remote'`, `/remote`): the page never opens a video stream
  (`player.stopped = true`). `push_follow()` sends `{type: "follow", port, device}` to a user's
  remote-mode pages whenever the port they're playing on another device changes. It works the
  other way too: picking another TV on a following phone sends `{type: "switch", port}`, and
  `switch_followed()` tells the followed page `{type: "setport", port, by}` so it switches as well.
- Gestures: `attachGestures(el, {onDir, onTap, onLong})` in `index.html` (pointer events; first
  arrow after 40 px, then one per 100 px; repeat every 280 ms after holding 650 ms; long press 550 ms). Used by the player
  layer `#glayer` (off by default) and the remote-mode touchpad `#pad`.
- Ports: `POST /api/admin/ports...` → DB → `Remotes.add()` (driver) and `sync_go2rtc()`, which
  POSTs the new YAML to go2rtc `/api/config` and restarts it via `/api/restart`.
- Status: `GET /api/ports/{id}/status` merges the driver status and the no-signal state.
  `SignalWatch` grabs `frame.jpeg` from go2rtc every 4 s, shrinks it to 8×8 RGB and calls it
  "no signal" when it's one flat colour (MS2109 #1 sends black) or the 8-bar test pattern
  (MS2109 #2 sends colour bars), for 2 checks in a row, or when the card is unplugged.

API: see the `@routes` decorators in `server.py` (grouped by section banners).

## Conventions

- Python 3.12, standard library + pinned deps in `app/requirements.txt` (pin exact versions;
  pyatv 0.18 needs **srptools 1.x**: 2.0 breaks Apple TV pairing).
- No frontend framework, no bundler: edit `index.html` / `login.html` directly. The page script is
  one `<script type="module">`; keep helpers before the classes that use them at load time.
- Admin-only UI and endpoints for anything that changes settings. Viewers only watch (and use the
  remote if granted).
- User-facing text: short, plain English, says what to do next.
- Never log or return secrets (Google client secret, session tokens, VLC tokens, pairing keys).
  VLC link tokens and invite tokens are stored hashed.

## Checking changes

There is no test suite; check what you touch:

```sh
python -m py_compile app/*.py                                  # syntax
python - <<'EOF'                                               # page script syntax (needs node)
import re, pathlib, subprocess, tempfile
s = pathlib.Path("app/static/index.html").read_text(encoding="utf-8")
js = re.search(r'<script type="module">(.*?)</script>', s, re.S).group(1)
f = pathlib.Path(tempfile.gettempdir()) / "tanchtv-page.mjs"; f.write_text(js, encoding="utf-8")
subprocess.run(["node", "--check", str(f)], check=True); print("page script OK")
EOF
sh -n go2rtc/capture.sh                                        # shell syntax
```

Then run it for real on a host with a capture card (`docker compose up -d --build`) and check
the page, `docker logs tanchtv-app` and `docker logs tanchtv-stream`. The UI also starts on any
machine (`cd app && DATA_DIR=../data python server.py`), but ports need Linux sysfs and go2rtc.

## Deploying an update

On the server, in the checkout: `git pull && docker compose up -d --build`. Only `tanchtv-app` is
rebuilt; restart `tanchtv-stream` when `go2rtc/capture.sh` changes. App restarts reconnect open
pages automatically, but a page kept open across several deploys runs its old code until reloaded.

## Hardware and protocol quirks (learned the hard way)

- **MS2109 cards**: identical vendor/product/serial, so identify by USB path; 1080p only as MJPEG,
  30 fps max; with no HDMI input they keep sending frames: one sends flat black, another its own
  colour bars (see `no_signal_pattern`). Audio is a separate ALSA card on the same USB device.
- **Audio**: `aresample=async=1` in `capture.sh` is essential; without it WebRTC sounds robotic.
- **go2rtc**: its MPEG-TS has no PCR (VLC drifts ~10 s behind), so VLC links remux with ffmpeg
  (`-pcr_period 20`); its RTSP AAC track sends nothing, so VLC links take Opus and convert to AAC.
- **VLC link sources**: `stream_links.port_id` + `follow`. Follow = `LAST_PORT[creator]`, the TV last
  switched to on any of their pages (a page just opening on its saved TV doesn't count). `vlc_stream`
  re-checks every 1.5 s and swaps the ffmpeg process inside the same HTTP response, with
  `-output_ts_offset` = seconds streamed so timestamps keep rising; VLC plays through it (~2 s gap).
  `preload` keeps streams warm so the first viewer doesn't wait 10–20 s.
- **iPhone Safari**: autoplay only muted (the page starts muted + "Tap to start"); no WebRTC
  `loadeddata` on the helper element, so `TvPlayer.onwebrtc` switches on real inbound frames;
  start MSE before WebRTC on iOS.
- **Background tabs**: `TvPlayer.background = true` stops VideoRTC from disconnecting when the
  page is hidden; a Web Lock keeps Chrome/Edge from freezing the tab.
- **Apple TV (pyatv)**: always pair from scratch (old credentials attached = no PIN shown);
  tvOS 26 accepts Companion HID Sleep/Wake, older tvOS needs the Home-hold fallback; the wake
  command may leave HDMI off until a key press, so wake also presses Home; power state from
  Companion and MRP disagree right after changes (treated as "on if either says on").
  `BaseRemote` uses `self._wake` (an asyncio.Event): don't name driver methods `_wake`.
- **Android TV**: pairing certificates per port in `data/ports/<id>/atv_*.pem`; ADB is optional.
  Text goes in through the input method, which only works in fields that use the system keyboard
  (e.g. the home-screen search). YouTube and Netflix draw their own keyboards and ignore both that
  and letter key presses: for YouTube the driver opens `vnd.youtube://results?search_query=…`
  instead; Netflix has no search link that works. Walking Netflix's letter grid blind was tried
  and rejected: rows wrap at the edges, coming down from the wide space/delete keys lands under
  their middle, presses faster than ~3/s get dropped, and once the focus guess was off an OK press
  started playing a show. Don't ship it without checking the focus (e.g. from the captured picture). Launch YouTube with `vnd.youtube://`: an `https://` link opens an
  "Open with" chooser when another app (e.g. Downloader) also handles web links.
- **Apple TV text**: pyatv `keyboard.text_set` works wherever tvOS shows its keyboard, YouTube included.
- **HDCP**: none on the capture path; DRM apps may show black. **CEC**: not wired on MS2109.
